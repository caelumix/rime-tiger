# 上游兼容说明

本项目以虎码官方实现的真实 Rime 行为为兼容目标。用户可见的扩展只有
`/` 分类符号和 `;` 快符；其余差异用于改善可维护性、错误诊断或性能，
不应改变普通输入的候选、切分和提交结果。

## 来源与许可

原始仓库中的 `LICENSE` 是 GNU GPL version 3 完整正文，
本项目采用 GPL-3.0-only，并在此说明工程化修改和功能扩展。

整句解码算法、输入行为、码表、字频、符号表和模型来自参考实现，
模型不随源码或运行 ZIP 分发，其许可仍以原始发布说明为准。

## 同步基线

当前基线为方案版本 `1.2`（2026-09-10 更新包）。参考副本无公开提交记录，故使用
以下哈希标识其内容：

```text
7e120a07ae447b54a0f1c0bcbe73ba9d1dfffcc3586a67020ba74441fcfaa876  lua/tiger_sentence.lua
4b3f80b34084bc3e2f9eb36dca6f0d1eafa8f3a797fef47919cfcb39ac519864  tiger_sentence.schema.yaml
9b45c4a2f179d42585d5cc1439bfbcb5a585520f0de3ce83232180990e5cc9b1  symbols.yaml
```

模型身份为：

```text
e3953f8f1526b871eb81fe887a8ae4a6edf79edffd33e388b95e2915adadb2d3
```

对照工具通过 `--reference` 接收参考目录，目录名称和位置不限。
测试会先核对上述源码、公开码表、字频和模型身份。

实现遵循 RimeInn 的
[Rime 开发规范](https://github.com/rimeinn/agent-skills)，包括 Lua 组件、
生命周期、组件管线和方案配置约定。这些约定用于组件接线、状态管理
和资源释放，不参与输入算法定义。

## 保留差异

差异只有三类：用户可见扩展（`/` 符号、`;` 快符），工程结构（管线、会话状态、
错误处理、词典与白名单存储、模块拆分、孤立惩罚的 oracle 双实现），
性能取舍（页缓存，以及实测后未采纳的两项上游优化）。除此之外的输入行为
必须与参考实现一致，由下面的对照命令以零差异强制。

| 类别 | 实现差异 | 依据与验证 |
| --- | --- | --- |
| `/` 符号 | `/` 引导分类符号；单独输入时保留候选，空格提交 `/` 或 `／` | 原生测试覆盖半角、全角、`/szq`、翻页和选重 |
| `;` 快符 | 空闲时引导快符；组合输入中仍表示二选 | 原生按键和连续输入回归 |
| Rime 管线 | 使用模块路径、matcher、ascii_segmentor 和独立符号表 | 普通输入逐键对照，扩展入口单独测试 |
| 会话状态 | `env` 保留状态引用，context 属性只存会话编号 | 双会话交错输入和组件释放回归 |
| 错误处理 | 输入替换失败时保留原输入；配置和目录 API 异常向上传播 | 故障测试覆盖全部显式报错位置 |
| 模型 | 只支持实际分发的 `TCSKNM02` | README 和 iOS 验收资料均指定 `02`，没有 `01` 模型 |
| 词典 | 明文码表构建为 `TCSLEX04`，候选按需解包 | 全部 14,374 个编码和 15,369 个候选对照一致 |
| 模型缓存 | 分页缓存限制为 2 MiB | 内存和延迟消融见下文 |
| 未采纳的上游优化 | 一元组哈希表与解码证据复用 | 两者实测均无收益，见性能段 |
| 白名单 | 组件加载时读取明文文件，不写入二进制词典 | 27,930 个过滤结果一致，修改无需重新构建 |
| 编辑缓存 | 长前缀退格复用格网，选重边界只重建末端 | 15,936 个编辑步骤与完整重算一致 |
| 锁定状态 | 锁定候选存于会话状态，不写入 context 属性 | 原生按键与逐键对照覆盖锁定、解锁和提前上屏 |
| 内部结构 | 解码、模型、Rime 适配和测试接口按职责拆分 | Lua 静态检查、行为回归和原生部署通过 |

半角 `/` 与参考符号表的 `、` 映射不同。这是分类符号入口的一部分：首键必须
保留候选，才能继续输入分类编码。修改此行为时，应同时更新符号回归和本文。

高亮候选保留兼容回退。librime 1.10.0 提供 `Context::Highlight`，而
librime-lua 在 2025-06-29 才加入对应绑定，并在底层缺少方法时返回 `false`。
当前实现先检查方法能力，再回退到 `segment.selected_index`，只影响候选浏览。

参考实现把 `punctuator/digit_separators` 显式置空，本实现同步该配置。
空闲数字已由 Lua 直接上屏，小数点也由 Lua 的 `dot_armed` 处理，
因此该项在本地实现中不改变可见行为，仅保持方案配置一致。

## 已对齐的输入行为

- 已提交前缀继续参与后续候选上下文，覆盖“反刍”和
  “汨罗江江水汩汩”等切分与候选回归
- 合法切分先竞争前 20 项，再按已提交文本过滤，不补齐被过滤的位置
- 浮点评分保持参考实现的结合顺序，避免接近同分的候选换位
- 自动上屏沿用参考实现的候选裁剪、同文合并和空码提交规则
- 128 码限制只计算尚未提交的输入
- 一码字、显式选重、前导零、浏览候选和退格行为与参考实现一致
- `Tab`/`Shift+Tab` 高亮后继续输入字母固定该候选的文本与编码边界：
  开启提前上屏时提交已确认部分，关闭时只固定边界；退到边界以内即解锁
- 空码顶屏的唯一性与强置信判断计入合法的非首选重码单字：
  `hx` 的候选“心/忄”以及 `hp`、`yc` 等整段单边不再在继续输入时提前提交首选单字
- 无候选时按空格只重置会话，不改写组合输入
- 码表版本注释可选；空字频会关闭高频过滤和孤立惩罚

参考源码中的 `implicit_rank_allowed` 没有跨组件共享，因此原生行为在
`xrxbj` 提交“反”后仍可继续选择“刍”，本实现以该实际行为为准。

## 验证结果

验证环境为 Lua 5.4 与 librime 1.16.1。

| 检查 | 数量 | 结果 |
| --- | ---: | --- |
| 解码对照 | 71,796 次 | 候选、顺序、文本、切分和名次一致；评分误差不超过 `1e-9` |
| 原生按键 | 384 个会话，12,655 个事件 | 处理结果、提交、剩余输入、预编辑和候选差异为 0 |
| 自动上屏 | 同一原生输入集 | 两端均提交 200 次、258 字 |
| 编辑缓存 | 15,936 个步骤 | 与完整重算差异为 0 |
| 显式错误 | 69 个报错位置 | 69/69 均由故障测试实际触发 |
| 清理与幂等 | 重复运行及失败注入 | 临时目录清空，旧输出在失败时保留 |

固定案例包括 `xrxbj`、`korylkugkugkskorkor`、
`kormylkugkugkskorgkorg`、`hxq`、显式选重、锁定与解锁、
重复歧义输入和长连续输入。测试只使用公开码表、字频和示例文件。

原生差分同时报告参考实现自身的增量缓存偏差：`xrxbj` 的 4 个
回退步骤上，参考实现的缓存结果与其完整重算不一致；本实现的编辑缓存
在上述全部步骤与完整重算一致。

## 性能取舍

性能测试使用固定种子 `72631`，共 67 个不超过 128 码的输入。
每个进程执行 1,959 次追加和 1,892 次退格，三次独立运行取中位数。
时间为 CPU 时间，峰值 RSS 来自 `/proc/self/status`。

| 实现 | 峰值 RSS（MiB） | 追加均值（µs） | 退格均值（µs） |
| --- | ---: | ---: | ---: |
| 当前实现，2 MiB 页缓存 | 30.164 | 383.411 | 46.508 |
| 参考实现 | 44.539 | 332.092 | 54.546 |
| 当前实现，8 MiB 页缓存 | 40.844 | 372.023 | 47.718 |
| 当前实现，不缓存路径惩罚 | 31.312 | 488.080 | 154.890 |

当前实现相对参考实现减少 14.375 MiB 峰值 RSS（32.28%），
追加均值慢 1.155 倍，退格均值快 1.173 倍。参考实现在 2026-09-10 的更新包中
改为按路径增量缓存孤立惩罚、构建一元组哈希表并惰性生成切分文本；本实现
同步了路径级孤立惩罚与惰性切分，因此本文曾记录的“追加均值加速 10.88 倍”
不再成立，差距也从追加 2.058 倍、退格 4.375 倍收窄到上表数值。

该表为一次运行中三次采样的中位数，不等于稳定分辨率：不同运行之间峰值 RSS
波动约 1 MiB、追加与退格均值波动约 10%（本实现的追加均值在不同运行中落在
350 至 385 µs，参考实现的退格均值落在 44 至 56 µs）。因此只据此判断量级与方向，
不据此判断 1% 级差异。2 MiB 页缓存比 8 MiB 少用 10.680 MiB，而追加与退格
均值差异都在上述波动内（-2.97% / +2.60%），所以不扩大页缓存。
去掉路径惩罚缓存后追加慢 27.30%、退格慢 233.04%，远超波动范围，
该缓存是这个收益的来源。

路径级缓存是一处刻意的重复实现：整串重算保留为
`model.reference_isolation_penalty`，只供回归当 oracle 使用，
解码热路径一律走 `decoder.path_isolation_penalty`。
`tests/decoder.lua` 对公开码表候选、长连续输入和锁定路径断言两者给出同一
惩罚值，漏传 `edge_chars` 或缓存失效会直接失败。

参考实现这个版本还有两项优化经实测后未采纳：一元组哈希表只增加约 0.75 MiB
堆而不改变耗时（本实现的 `score_cache` 已经吸收重复查询）；解码证据复用
在“先无证据解码、再带证据解码”的 48 到 128 码输入循环上与不启用时差异在
噪声以内，因此不保留该缓存分支。上表把两者都排除在外，其余实现差异只来自
工程结构。

切分串改为惰性生成（读取 `segmented` 时才计算），追加均值因此再降约 10%、
退格再降约 45%；`tests/decoder.lua` 与原生对照都会实际读取该字段。

长前缀退格只裁去失效格网。删除的首字符为 `;`、`'` 或数字时，
选重解析可能改变末端，此时只重建该位置的边；引入该复用时，
无复用的全量重算退格均值高出 20.9 倍。

## 构建与分发边界

源码不跟踪 `lexicon.bin`、生成的 `ranks.lua` 或模型二进制。
运行 ZIP 在临时目录生成词典，包含公开示例改名后的补充语料和白名单，
`models/` 只放模型元数据。连续构建字节一致；生成失败时保留旧包并清理临时文件。

模型元数据位于包的 `models/` 目录，附件则按元数据中的日期和 SHA-256 单独上传到 Release。

## 复现与同步

```sh
tools/check.sh all
tools/check.sh native
tools/check.sh comparison --reference "/path/to/reference" --quick
tools/check.sh comparison --reference "/path/to/reference"
python3 tools/compare_lexicon.py --lua /path/to/lua5.4
python3 tools/compare_lexicon.py --lua /path/to/lua5.4 --whitelist
```

`all` 检查格式、类型、模型身份、行为和错误覆盖；`native` 检查组件交互；
快速对照适合日常修改，完整对照还会执行全量解码、编辑和性能测量。
完整对照的解码部分按四个过滤/重码组合并行分片，合并后的计数与串行一致。
所有临时生成物由检查入口清理。

同步新的参考版本时，先更新基线身份，再按变更位置修改实现和回归。
普通输入出现差异时，对照命令会失败。只有新增公开功能或经过量化的性能取舍
可以加入“保留差异”，并应同步更新用户文档和测试。

参考实现的内部签名变化会影响对照驱动：`tests/comparison.lua` 直接调用
两端的 `decode`，因此参考实现新增位置参数时必须同步调整该调用点。
